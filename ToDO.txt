Les silver labels ne sont pas utilisés dans une boucle d’auto-apprentissage.
Ils servent à :
initialiser ton modèle
donner du signal de structure (hiérarchie)
stabiliser les embeddings des classes
forcer un modèle léger (InnerProduct + BCE) à comprendre la position hiérarchique d’une classe
➡️ À ce stade, il n’y a pas de risque de feedback loop (puisque tu ne vas pas re-entraîner le teacher dessus plusieurs fois).

Si tu entraînes ton modèle avec :
3 labels verticaux → parfait
5 labels horizontaux (siblings) → incohérent
3 classes concurrentes → bruit
1 seul label → manque d’information hiérarchique

RAW = précision sémantique
HIERARCHICAL = cohérence structurelle

Raw embeddings (base_category_embeddings)

✅ Très précis - Chaque classe a son embedding spécifique
✅ Meilleur coverage - Peut distinguer entre classes similaires
❌ Moins de generalization - Si le review est ambigu, peut choisir une classe trop spécifique
Propagated embeddings (hierarchical_embeddings)

✅ Plus de generalization - Les embeddings des parents influencent les enfants
✅ Meilleure consistency - Respecte mieux la hiérarchie
❌ Moins précis - Les classes enfants deviennent plus similaires à leurs parents
❌ Peut perdre des nuances - Toutes les sous-catégories de "baby_food" deviennent trop similaires
